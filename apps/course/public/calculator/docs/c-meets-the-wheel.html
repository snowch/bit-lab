1. An unsigned loop with no stopping test

uint8_t a[2];        // an array of n = 2 elementsuint8_t n = 2;uint8_t i;for (i = n - 1; i >= 0; i--)   // clear a[1], then a[0], then stop    a[i] = 0;

The loop should clear indices 1 and 0, then stop. Step through until R0 changes from 0 to 255. Does the condition i >= 0 ever become false when i holds only values from 0 to 255?


      

      

      

    

  

  

    
2. 127 + 1

    
int8_t x = 127;x = x + 1;

    
Predict the model’s R0, C (carry out) and V (signed overflow) for 127 + 1. In the C code, x becomes an int before the addition. The sum is 128. Converting that sum back to int8_t is the step whose result is implementation-defined in C11.

200 is outside the range −128 to 127 of int8_t. C11 allows an implementation-defined result or an implementation-defined signal. Step through to see what happens when this model keeps the low byte and reads it as a signed value.

// read digits as positive, negate at the endint8_t acc = 0;for each digit d: acc = acc * 10 + d;return negative ? -acc : acc;

    
This pseudocode stores each partial result in an int8_t. Step until R2 first shows a negative signed value. Which digit caused the positive value to exceed 127?

    

      

      

      

      

      

    

  

  

    
6. Detecting a wrap in C

    
uint8_t a = 3, b = 5;uint8_t d = a - b;if (d > a) /* wrapped */

    
The C subtraction produces the int result −2, which becomes 254 on conversion to uint8_t. Compare R2 with R0 after the subtraction. Does the stored result exceed the original value?

    

      

      

      

      

      

    

  

  

    
7. %d and %u

    
int8_t x = -2;printf("%d", x);   // -2printf("%u", (unsigned)(uint8_t)x);   // 254

    
In C, %d receives the promoted int value −2. For %u, first convert to uint8_t to get 254, then to unsigned to match the format. Step through and compare the two readings on the R0 row.

    

      

      

      

      

      

    

  

  

    
8. −128 / −1

    
int8_t x = -128, d = -1;int8_t q = x / d;   // +128 does not fit

    
In the C code, both operands become int before division, so +128 fits in the expression. Converting that value back to int8_t is implementation-defined in C11. Watch what the trace keeps when it stores the quotient in R2.

    

      

      

      

      

      

    

  

  

    
9. The check that vanished

    
int x = 127;if (x + 1 > x)    puts("no overflow");

    
The example uses a signed int. Whenever x + 1 has defined behaviour, the result is greater than x. The trace illustrates how an optimiser can replace the comparison with true. At INT_MAX the addition would already have undefined behaviour, so the comparison cannot safely check for it.

    

      

      

      

      

      

    

  

  

    
10. 255 + 1, and detecting it

    
uint8_t a = 255, b = 1;uint8_t s = a + b;if (s < a) /* carried */

    
The C addition produces the int result 256, which becomes 0 on conversion to uint8_t. After the model adds, compare R2 and R0 and check C and Z. Can the stored sum be smaller than an input even though both inputs were positive?

    

      

      

      

      

      

    

  


  

    
Catching these

    
Use the destination type’s range before storing a value. The model’s C and V flags explain what happened at eight bits. A C check needs to account for the type in which the expression was evaluated and the type it is stored in.

    
Choose types with headroom

    
Compute in a type wide enough for the operation. Before converting to a smaller signed type, compare the result with that type’s minimum and maximum. In C11, int8_t and uint8_t operands become int in these arithmetic expressions, because int can hold every value of either type.

    
Check before, not after

    
Checking after the operation is scenario 9: the compiler may assume the overflow never happened and delete the check. Write the test in terms that cannot overflow themselves:

    
if (b > 0 && a > INT_MAX - b)  /* a + b would overflow   */
if (b < 0 && a < INT_MIN - b)  /* a + b would underflow  */
if (x == INT_MIN)               /* -x and abs(x) are unsafe */
if (d == -1 && x == INT_MIN)     /* x / d is unsafe        */

    
Use checked arithmetic

    
GCC and Clang offer __builtin_add_overflow(a, b, &r), __builtin_sub_overflow and __builtin_mul_overflow. These return true when the exact result cannot fit in the destination type of r. C23 offers ckd_add, ckd_sub and ckd_mul in <stdckdint.h>. The generated instructions depend on the compiler, types and target.

    
Let the compiler warn

    
With GCC, -Wtype-limits can flag an unsigned index compared with zero, and -Wconversion can flag a narrowing conversion. Use -Wformat to check format arguments. Which diagnostics fire depends on the compiler and options.

    
Check runtime behaviour in tests

    
-fsanitize=undefined can report signed arithmetic overflow for cases your tests execute. With Clang, -fsanitize=implicit-conversion can also report conversions that change the value. That separate check matters when the arithmetic fits in int but the destination is narrower.

    
Decide what wrap means

    
Conversion to an unsigned type is defined modulo one more than its maximum. For modular arithmetic, account for any promotions before the operation. GCC and Clang’s -fwrapv defines wrapping for signed addition, subtraction and multiplication. It does not change how C treats division by zero or how a narrowing signed conversion is defined.

    
Test the edges on purpose

    
INT_MAX, INT_MIN, 0, −1, UINT_MAX, and one short of and one past every size limit in the program. Part 3's "does it fit" drill is this habit in miniature.

  • Each trace runs on a machine with four 8-bit registers and the N Z C V flags, computed the way the Bit Lab does it: subtraction is A + NOT B + 1, C is the carry out of the top bit, V is the carry into the top bit XOR the carry out.

  • The trace highlights the source line it illustrates and underlines the part being discussed. The assembly-style listing describes the model’s steps.
    • 
      
  • An outline marks a changed bit. The flags row is highlighted when the step produced new flags. In these traces SUBS and ADDS update flags, while a plain move leaves them alone.
    • 
      
  • The model performs each operation at eight bits. In C, an operation and its later assignment can use different widths and have different range rules.
